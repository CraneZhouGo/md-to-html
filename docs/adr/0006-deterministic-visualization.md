# 确定性图形化：可以重排结构，不可改写文字

## Status

accepted

## 决定

渲染器不再逐字平移 markdown，而是允许**结构级图形化重排**。边界、判定机制、优先级、实现技术与失败策略一次性定死：

**1. 边界（这是 ADR-0003 的细化，不是推翻）**

| 允许 | 禁止 |
|---|---|
| 改 DOM 结构与版式：表格→对比卡片、列表→步骤流 | 新增、删除、改写、摘要任何文字 |
| 从文字里**提取**已有数值画条形/折线 | 由模型生成新文字（解读、TL;DR、结论） |
| 把"术语：定义"重排成定义卡片 | 把两个句子合并、拆开或重新排序 |

**硬约束**：图形化后的每一个文字字符都必须仍可被 Ctrl+F 搜到、被鼠标选中复制。这条是判断"这是呈现还是改写"的唯一客观测试。

**2. 判定机制**：混合。默认零标记——任何普通 `.md` 丢进来都能出效果，不用改写历史文档；渲染器用启发式识别；作者可用 **HTML 注释**覆盖：

```markdown
<!-- md: no-visual -->     关闭下面这一段（或整篇）的图形化
<!-- md: table -->         强制按表格卡片处理
<!-- md: card -->          强制按定义卡片处理
```

用注释而非 fenced code 块，是因为注释在 GitHub、编辑器预览里原生不可见，不破坏"真源就是普通 markdown"（ADR-0001 双表示）。

**3. 优先级**（依据实测：真实文档中表格行占 46%、列表项 81 个、代码块 2 个）

- **P0 表格**：≤4 列 → 对比卡片；含可解析数值列 → 横向条形 + 数字原值标注；>12 行 → 保留真表格 + sticky 表头（不做图形化）。
- **P1 无序列表**：呈"术语：定义"形态 → 定义卡片；短句并列 → 清单块。
- **P2 有序列表**：含步骤/阶段语义（"首先""然后""Step"）→ 步骤流（编号 + 连接线）。
- **P3 引用块** → 提示块（note/tip/warning 由首词判定，判不出则中性）。
- **代码块只做语法高亮，永不图形化。**

**4. 实现技术**：优先 **CSS/HTML 结构重排**（文字是真实文本节点）；只有真正的数值图表用**内联 SVG**。**永不用 Canvas**。

**5. 失败策略**：**宁可不画**。图形化只在所有严格条件同时满足时启用（列数 ≤4、单元格文字 ≤40 字、数值可解析、嵌套 ≤1 层、注释未关闭）；任何一条不满足就原样渲染 markdown 的标准形态。

## 为什么

- 测量显示真实输入是表格与列表的堆叠，而"HTML 图形化"的直觉对象（架构图、流程图、代码 diff）在实际文档里几乎不存在。优先级因此按出现频次而非想象力排序。
- 允许生成新文字会让阅读面与真源**语义分叉**：读者看到的是模型的解读，agent 读到的是原文，双表示（ADR-0001）随之失效，且没人能核对图说的对不对。硬约束"每个字符仍可搜索、可复制"把这条边界变成可自动化验证的断言。
- 用注释做覆盖而非新语法：真源必须能直接丢进 GitHub 阅读。任何新语法都会让"双表示"变成"两套源码"。
- CSS 结构重排的文字可搜索、可复制、随主题变色、体积近零；SVG 文字难复制；Canvas 文字完全不可搜——对一个以"能读、能找、能复制"为卖点的制品，Canvas 是自毁。
- 画错的图**不会被 diff 审查发现**（HTML 的 diff 看不出一张表被重画错了），所以默认必须保守。

## Considered Options

- **纯启发式、无逃生门**：一定会在某些文档上画错且无法关闭。拒绝。
- **纯显式标记（要求作者写指令）**：要求改写所有历史文档，阻力过大，且真源被污染。拒绝。
- **允许模型生成解读文字**：语义分叉，违反 ADR-0003/0001。永久拒绝。
- **Canvas / 截图式图形**：文字不可搜索复制。拒绝。
- **表格一律图形化（含 >12 行的大表）**：大表转卡片后会丢列对齐与扫读能力，反而更差。拒绝。

## Consequences

- 需要一条自动化测试：渲染后提取 `body.innerText`，断言其与真源纯文本的字符集一致（顺序可因重排而变，但不得增删字）。这是本 ADR 的守门测试。
- 启发式规则必须集中在一个可读的模块里并逐条配单测，因为"判错了"是常态，需要能被快速修正。
- 每个 P0–P3 规则都要有一个 `no-visual` 的对照样本，防止规则退化成"必须靠图形化才能看"。
- 颜色与图形语言来自 ADR-0004 的 token 层，图形化不得引入新的颜色常量。

## 实施现状（2026-10-30）

已落地（`src/visualize.mjs`）：

- **P0 表格 → 对比卡片**：列 ≤4、行 ≤8、所有单元格 ≤40 字；不满足则保留表格（含数值列右对齐）。
- **P0 数值列 → 条形图**：列内 100% 可解析为纯数字、≥3 行、无负数、最大值/最小值 ≥1.2、非步长为 1 的序号列。条形按列内最大值归一，画在单元格底部（文字仍在上层，可选中可搜索）。**有条形图的表一律不卡片化**——否则横向对比会被打散。
- **P1 列表 → 定义卡片**：每一项都形如「术语：定义」、术语 ≤18 字、≥2 项、无嵌套。
- **P1 列表 → 定义卡片**：每一项都形如「术语：定义」、术语 ≤18 字、≥2 项、无嵌套。
- **P2 有序列表 → 步骤流**：3–8 项、每项 ≤100 字、无嵌套、无代码块。
- **注释开关**：`<!-- md: no-visual -->` / `visual` / `table` / `cards` / `steps`，以及 front-matter `visual: off`。
- 守门测试覆盖：三类转换各一例、两个开关、以及"图形化后文字仍完整"。

未落地：

- 折线图与多列对比图（只做了单列横条）。
- 局部行数超限时的分页或折叠呈现。

已知取舍：卡片化会让"逐行横向对比"变成"逐卡纵向对比"，对 8 行以内的短表更好读，对更长的表更差——这正是把行数卡在 8 的原因。
