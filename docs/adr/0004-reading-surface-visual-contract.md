# 阅读面的视觉契约

## Status

accepted（2026-10-30 依据实测证据修订一次，见文末"修订记录"）

## 决定

单文件制品的视觉规则一次性定死，作为渲染器的实现契约。所有数值以 CSS 自定义属性定义在 `:root`，便于个性化覆盖层只覆盖变量、不改结构。

- **骨架**：单栏长文为默认；**右侧**浮动窄栏 TOC（240px）在 ≥1100px 出现，窄屏收进顶部按钮。不做左侧常驻目录。
- **排版**：正文 **17px / 行高 1.75 / 正文列 max-width 780px**（用 px，不用 ch——中文字形宽度让 ch 失真）；段落下边距 14px；系统字体栈，零网络字体。
- **字阶**：h1 34px / h2 24px（上边距 40px、下 12px）/ h3 19px（上 28px、下 8px）。h2 的上边距是页面上唯一的大节奏来源。
- **位置感**：TOC 高亮当前节（唯一必做项）；sticky 当前章节名放在 56px 顶部栏内，滚过首屏后才出现；**不做阅读进度条**。scrollspy 用 `scroll` 事件 + `getBoundingClientRect().top <= 88` + 120ms 去抖，**不用 IntersectionObserver**（实测 4/4 范本都不用）。
- **对比度**：正文文字对比度 **≥ 10:1**（WCAG AA 只要 4.5:1，但实测范本普遍在 10:1 以上；唯一 5.0:1 的样本读起来明显发灰）。着色块（提示块）一律用低透明度 soft token，不用纯色大色块。
- **装饰预算**：只有排版、细线分隔和一处强调色。无卡片、无阴影、无渐变标题、无图标字体。唯一例外是语义提示块（note/tip/warning）。
- **主题**：跟随系统深色模式 + 手动切换（存 localStorage）。**本制品不为打印设计**：不写任何 `@media print` 规则；打印需求由原始 markdown 承接（页顶提供“查看 / 下载原始 .md”入口，指向与制品同源的真源）。
- **首屏概览**：允许由标题结构机械生成的章节概览（标题、层级、该节行数），不允许生成新文本。
- **代码块**：13px / 1.6，`white-space: pre` + `overflow-x: auto`，**无行号**（复制时会污染），**有复制按钮**；浅色主题下代码块仍用深底（与页面主题解耦，实测 3/5 范本如此，且对比度更好）。
- **表格**：外层 `.tbl-wrap` 横向滚动 + 13.5px 字号 + 表头 sticky（`top: 0`）。
- **超宽内容**：表格、代码、图各自进独立横向滚动容器，一律不换行；图片按容器缩放并允许点击放大。
- **折叠（渐进披露）**：只用原生 `<details>`，不用 `display:none` 自造折叠；页顶提供“全部展开”按钮（Ctrl+F 靠它兑底）。

## 为什么

读者是"只打开一次、读九十秒、然后走人或行动"的非技术同事（D4）。因此样式的目标是**降低放弃率**，不是"显得专业"。

- 左侧常驻目录吃掉约 20% 宽度，把正文挤窄，且"手册感"会预先宣告"这很长，先别读"——恰好触发要解决的放弃行为。
- 780px 正文列是实测范本的共同区间（md-reader 800、onedoc 780、xdossier 760、he 各样本 `p{max-width:680px}`）；所有 1100–1240px 的大容器都只是**给侧栏留位置**，正文仍然靠 `max-width` 收窄。
- 系统字体栈是唯一可行选择：内嵌一套中文可变字体 3–5MB，直接摧毁"能发给别人"这个核心卖点（ADR-0002）。实测 5/5 单文件实现都不用 webfont，其中两个仓库的注释里能看到"为守离线而删掉字体导入"的痕迹。
- **为什么不做打印样式**：打印是 HTML 最容易做、最容易做错、且最容易让两套样式漂移的一层（实测两个成熟单文件项目都在这里出了事故：`md-reader` 的折叠章节在 PDF 里直接缺章）。本项目的读者是“收到文件、打开、读九十秒”的人，不是打印的人；真需要纸面稿，要的也不是一份被重新排过版的 HTML，而是**原始 markdown**——可编辑、可 diff、不需要任何样式承诺。这同时让制品少掉一整套媒体查询与分页控制。
- 对比度 10:1 不是洁癖：范本里唯一的低对比样本（Solarized 5.0:1）是我们最该避免的形态——读者在笔记本低亮度或投影仪上会直接读不动。
- **折叠是最容易埋雷的地方**：任何用 `display:none` 实现的折叠都会同时破坏 Ctrl+F 与打印。实测两个项目都踩了——`md-reader` 的打印样式没有展开被折叠的章节，导出 PDF 会缺章；`onedoc` 的 README 宣称"Ctrl+F 能搜全部"，但它的 CSS 写着 `[hidden]{display:none}`。本仓库虽然不做打印，但 Ctrl+F 那一半依旧成立，所以用原生 `<details>` + 页顶“全部展开”。

## Considered Options

- **双栏手册布局（左侧树状目录常驻）**：与"读"的定位冲突，宽度代价高。拒绝；需要手册形态时那是另一档产品（ADR-0001 的升级档）。
- **内嵌网络字体 / 中文可变字体**：体积与离线要求双双不允许。拒绝。
- **装饰性设计（卡片、阴影、渐变）**：制品要在别人的浏览器缩放、投影仪、打印环境下打开，依赖精细像素的装饰都会劣化；排版不会。拒绝。
- **进度条**：不做（与 md-reader、xdossier 相反，见下"偏离共识"）。
- **用 `ch` 定义行宽**：Tailwind Typography 用 65ch，其余全用 px。中文的 `ch` 按 "0" 计算，与实际行宽严重不符。拒绝。

## 偏离共识的三处（知情选择，可随时用一句话撤销）

1. **正文 17px（共识 16px）**：范本全是英文文档，16px 对中文偏小；中文阅读普遍需要略大字号。若视觉验收时觉得偏大，改回 16px 只需动一个变量。
2. **行高 1.75（共识 1.55–1.75）**：取区间上沿，理由同上（中文需要更多行距）。md-reader 默认 1.85，说明再宽也有人接受。
3. **不做进度条（2/5 范本有）**：进度条回答的是"还剩多少"，长文档读者问的是"我在哪、这段该不该读"；后者由 TOC 高亮与章节名回答。若人因测试显示定位困难，这是最先重开的条目。

## Consequences

- **一切视觉数值必须来自 `:root` 上的 CSS 变量**，禁止在组件里写魔法数字。这是个性化能力（ADR-0005）的前提，也使得换主题不需要改结构。
- 制品不含任何 `@media print` 规则，打印行为交给浏览器默认。页顶必须提供“查看 / 下载原始 .md”入口，且指向与制品同源的真源（双表示，ADR-0001）。
- 这意味着一整类工作被删除了：不再需要打印配色、分页控制、`break-inside`、链接后附 URL、打印时关掉 sticky 表头。少维护一套样式就少一处漂移源。
- 位置记忆需要浏览器本地存储；`file://` 下存储行为跨浏览器不一致，因此功能必须可缺失而无害。
- 首屏概览的分节行数在渲染时统计，与真源同源计算，不引入模型输出（ADR-0003）。
- 单文件制品常态体积 12–80KB（实测），前提是字体不内联、图形用内联 SVG；ADR-0002 的 2MB 告警阈值因此足够宽松。
