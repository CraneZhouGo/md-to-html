# 图示渲染：ASCII 图 -> 内联 SVG，文字仍是文字

## Status

accepted（细化 ADR-0006 的图形化边界）

## 决定

能被可靠识别的 ASCII 图，渲染成**内联 SVG**；识别不了的，退回文本图示（`<figure class="diagram" data-kind="ascii">`）。

**支持的四种源写法**（只认这四种，其余一律不画）：

| 写法 | 形状 | 例 |
| --- | --- | --- |
| 竖向分层 | `↓` 切分层，`├──/└──` 是层内兄弟 | 用户请求 ↓ Nginx ├── 实例 1 … ↓ Redis |
| 树形 | 一个头节点 + 分支，无箭头 | NFS/NAS ├── 应用 1：/data … |
| 单行链条 | 一行内的 `→` | 应用 → Mycat 集群 → 主库 / 从库 |
| 续行链条 | 首行节点 + 后续 `→ 节点` | GitLab → Jenkins → Harbor |

**不画的**（实测 12 张图里 3 张属于此类，全部退回文本）：多条互不相连的链、`─┐ ─┼ ─┘` 的框线汇聚图、节点超宽（>56 显示单位）或含逗号说明的链。

**排版规则**

- 层数 ≤5 优先竖排（上→下）；竖排放不下（宽 >820px）且横排放得下（宽 ≤820 且高 ≤820）才改横排；都放不下时选最长边更短的那个。
- 相邻层边数 >9 时走"总线"（一条汇流线 + 每端一个箭头），避免连线糊成一团。
- 颜色全部来自 `--accent` 与 `--text` 系变量，跟随主题与强调色；无外链、无脚本、无 `href`。

## 为什么

- **文字必须是文字**：SVG 的 `<text>` 可被 Ctrl+F 搜到、可选中复制；用路径描字或用 Canvas 会让搜索、复制、agent 读取同时失效。ADR-0006 里"Canvas 永不用"的那条对 SVG 也成立。
- **确定性**：布局由固定公式算出（字宽近似 × 文本宽度 + 固定间距），同一输入必得同一串字节，可与真源一起进 git diff 审查。
- **保守优先**：ASCII 图无法表达语义，硬解会画错；画错的图不会被 diff 审查发现（看不出一张图的节点关系错了）。所以只做四种能被严格语法锚定的形状，其余退回文本。
- 为什么不做真正的时序图/ER/状态机：那三种需要**结构化源**（参与者、消息序列、实体关系、状态迁移），从 ASCII 反解必然出错。它们应当从各自的 DSL 或 mermaid 子集生成，属于后续工作，且必须共用同一套 SVG 渲染与"文字仍是 <text>"的约束。

## Considered Options

- **把 ASCII 转成位图/路径描字**：搜索、复制、diff 全部失效。拒绝。
- **引入 mermaid 运行时**：几百 KB、需要 DOM 与网络字体假设，且产物不再是零依赖单文件。拒绝（若将来支持 mermaid 源，也应当自己解析子集，而不是打包运行时）。
- **解析框线汇聚图（`─┐ ─┼ ─┘`）**：语法歧义大（一位错位就改变拓扑），收益只覆盖 1/12 的图。暂不做。
- **所有图一律转 SVG**：会给"看起来像图但其实是一段日志/公式"的文本块画出错误结构。拒绝。

## Consequences

- 图里每个节点文字都必须原样出现在 `<text>` 中；有测试守着（`✓ SVG 里的文字是真文本节点`）。
- SVG 宽度上限 820px（正文列 800 + 余量）；超了会自动换朝向，再不行就退回文本。
- 新增图示类型时，只需在 `src/diagrams/` 里加一个解析器并复用同一套 SVG 输出与变量配色。
- 退回文本的图仍然保留 `data-kind="ascii"`，样式上按"图"排版（行高 1.16），不会变成难读的代码块。
