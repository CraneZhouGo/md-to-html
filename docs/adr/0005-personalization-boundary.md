# 个性化只作用于 token 层，且默认不写进文件

## Status

accepted

## 决定

个性化分三档，边界如下：

1. **允许的个性化范围：token 层**——颜色、字体族、字号、行宽、行高、线宽/圆角。**结构层一律不开放**：单栏/双栏、TOC 左右、折叠默认开合、是否显示首屏概览都不作为用户选项。
2. **身份标记的最简形态**：一个可编辑的"读者名"，出现在页眉与打印页脚（打印已取消，见 ADR-0004，故仅页眉）。**不做阅读痕迹**（高亮、书签、批注）——留待下一版，且届时需另立 ADR。
3. **存储分三通道，职责不重叠**：
   - `localStorage` —— "我的习惯"，本机生效，不触碰文件。
   - `--profile <file>` 构建期参数 —— "我要发出去的那一份"，偏好被内联成文件内的默认值。
   - 页面内"复制配置"按钮 —— 跨设备搬运（手工粘贴），不引入任何账户或服务。
4. **默认不污染产物**：身份标记与偏好默认只存在本机。只有显式使用 `--profile` 渲染时才写进文件，且此时页眉需标注"个性化副本"。
5. **确定性断言**：无偏好时，同一真源必须渲染出**逐字节相同**的文件（用哈希测试守住）。偏好只允许从上述两个注入点进入。
6. **不做跨设备同步**：零账户、零服务、零网络。

## 为什么

"每个用户独属的标记"与"同一真源渲染出同一产物"（ADR-0002）只能在**不同层**上共存：文件是一份，呈现是多份。这条边界必须一次划清，否则后续每次讨论都会重新吵一遍。

- **不做伴生 profile 文件**：`file://` 下 `fetch()` 本地 JSON 被 CORS 拦截，这条路在主要使用场景（双击打开）里技术上不可行。`md-reader` 正是踩了这个坑才改用 launcher 打包数据。
- **不做 URL 查询参数**：双击打开本地文件时根本没有查询串。
- **偏好必须能缺失而无害**：`file://` 下 `localStorage` 跨浏览器行为不一致（Chrome 共享 origin，Safari 部分场景隔离或禁用）。
- **只开 token 层**：结构层一旦可配置，视觉契约与响应式断点要做组合爆炸测试，且 ADR-0004 里"不做进度条""单栏默认"这些判断是有理由的、不该被用户随手关掉。token 层已经能满足"这是我的一亩三分地"这个心理需求。
- **默认不写进文件**是隐私要求：把带自己名字的文件发给客户，会让收件人看到一个不属于他的身份标记。

## Considered Options

- **开放结构层配置**（布局、TOC 位置、密度档位）：测试矩阵爆炸，且会侵蚀 ADR-0004 的判断。拒绝。
- **偏好写进文件默认值**（每人一份个性化文件）：破坏"同一真源同一产物"，也让"文件是公共的"这条边界消失。拒绝。
- **伴生 `<name>.profile.json`**：`file://` 下不可读。拒绝。
- **账户 / 云同步**：与"离线单文件"根本对立，且需要服务端。拒绝。
- **第一版就做高亮与批注**：这是批注系统（持久化、真源更新后旧批注的重新定位），成本高一个数量级，且会让"同一个文件发给十个人，十个人的文件开始不一样"。拒绝，留待下一版。

## Consequences

- 渲染器必须把全部视觉数值集中在 `:root` 的 CSS 变量上，个性化层只覆盖变量——这条在 ADR-0004 里已写死，此处是它的用途。
- localStorage 的键需要有命名空间前缀，且必须容忍写入失败（隐私模式、配额、浏览器禁用）。
- `--profile` 需要一份带版本号的 JSON schema，读到未知字段应忽略而不是报错。
- 需要一条哈希回归测试：同一真源 + 无偏好 = 相同输出。这是本 ADR 唯一的可执行断言。
- "个性化副本"标注只出现在用 `--profile` 渲染的产物里；普通产物不含任何个人标识。
