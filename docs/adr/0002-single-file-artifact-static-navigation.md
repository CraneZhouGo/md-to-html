# 单文件制品，导航在构建期静态生成

## Status

accepted

## 决定

渲染产物是**一个自包含 HTML 文件**：CSS 与 JS 内联，图片与字体默认外链、仅在 `--embed` 显式开启时内联。目录、锚点、章节编号一律在**构建期**静态生成并写入 HTML；运行时 JS 只负责折叠、搜索过滤与滚动高亮。每次渲染一个目录时，同时产出与该目录同源的机器可读索引（`index.md`）。

## 为什么

- 静态导航在被 JS 关闭、Ctrl+F、打印、agent 直接抓取 HTML 这四种情况下都还在；运行期生成的导航在这四种情况下全部消失。而 Mintlify 的基准显示，决定 agent 能否找路的正是索引地图（404/任务 2.23 → 0.11），不是标记格式。
- 单文件是本项目的存在理由："发给别人、对方双击就打开"。多文件目录会把这个卖点破坏掉，所以宁可体积大也不拆。
- 图片与字体默认外链：内联它们会让制品从几百 KB 膨胀到几十 MB，直接发不出去。

## Considered Options

- **超过阈值自动切分为多文件**：破坏"单文件可转发"这一核心卖点，且切分点由程序臆断。拒绝；只在超过 2MB 时**告警**，由作者决定是否精简内容。
- **运行期用 JS 生成目录与锚点**：实现简单、体积小，但在 JS 关闭、打印、抓取、Ctrl+F 场景下全部失效。拒绝。
- **默认内联全部图片与字体**：单次可达数十 MB。拒绝，改为 `--embed` 开关。

## Consequences

- 渲染器必须是纯粹的"markdown → HTML 字符串"转换，不依赖浏览器环境即可产出完整制品。
- 索引与目录必须同源生成：不允许从 HTML 反解析出索引，否则两者会漂移。
- 索引默认产出；`--no-index` 可为单独渲染某一篇时关掉。（早先实现里它是显式 `--index` 开关，与本 ADR 的承诺不一致，已改。）
- 2MB 告警阈值是配置项，不是硬编码。
- 制品的体积成本随内容线性增长，作者需为"发不出去"承担判断责任——渲染器只提醒，不替作者裁剪。
