# mermaid 子集：自己解析，不打包运行时

## Status

accepted（ADR-0008 的延伸：图示的源可以是结构化 DSL）

## 决定

支持 ` ```mermaid ` 代码块的四种子集语法，**自己解析成内联 SVG**，不引入 mermaid 运行时：

| 图型 | 首行 | 支持的语句 |
| --- | --- | --- |
| 流程图 | `flowchart TD / LR / TB / BT / RL`、`graph ...` | `A[文本]`、`A(文本)`、`A{文本}`、`A((文本))`、`A[(文本)]`、`A --> B`、`A -->|标签| B`、`A -.-> B`、`A --- B`、链式 `A --> B --> C` |
| 时序图 | `sequenceDiagram` | `participant X as 名称`、`actor X as 名称`、`A->>B: 文本`、`A-->>B: 文本`（虚线与实线） |
| 状态机 | `stateDiagram-v2` | `X --> Y`、`X --> Y: 标签`、`[*] --> X`、`X --> [*]`、自环 |
| ER 图 | `erDiagram` | `实体A ||--o{ 实体B : 关系`、`实体 { 类型 字段 }` 属性块 |

**任何一行解析不了，整块退回代码块**（原样显示 mermaid 源码）。绝不"猜一半画一半"。

## 为什么

- 用例图/时序图/ER/状态机都需要**结构化源**（参与者与消息顺序、实体与关系、状态与迁移）。从 ASCII 反解必然出错（ADR-0008 已论证），所以必须读 DSL，而 mermaid 就是这类图的行业默认写法。
- **不打包 mermaid 运行时**：它是几百 KB 的 JS + 需要 DOM 与字体假设，会摧毁"单文件、零依赖、离线"（ADR-0002）。自己解析子集，代价是支持的语法有限，收益是产物仍然是一个可 diff 的 HTML 文件。
- **失败即退回**比"尽力渲染"更重要：画错的图不会被 diff 审查发现，而一块原样显示 mermaid 源码的代码块至少是诚实的。
- 布局确定性：分层用"最长入边深度 + 环保护"，坐标由固定公式算出；同一输入必得同一串字节。

## Considered Options

- **打包 mermaid 运行时**：体积、DOM 依赖、产物不可控，且它的输出样式无法跟随本项目的主题变量。拒绝。
- **支持完整 mermaid 语法**：子图、样式、时序图的 loop/alt/Note、ER 的注释等，成本远超收益，且多数语法一旦支持不完整就会画错。只做子集。
- **从 ASCII 猜时序图**：不可靠。拒绝。
- **渲染失败时半成品展示**：会产出误导性的图。拒绝，一律退回代码块。

## Consequences

- 支持的语法是**白名单**；新增语法必须同时补测试与文档，否则会被当成"不支持"退回。
- 节点数、层数没有硬上限，但宽度超过 1100px 的图会被放弃并退回代码块（避免正文被撑爆）。
- 颜色全部走 `--accent` / `--text` 系变量：`.dg-diamond` / `.dg-round` / `.dg-terminal` / `.dg-lifeline` / `.dg-dot` 等类名与 ASCII 图示共用同一套配色。
- 图内文字仍是 `<text>` 节点，可搜可选中（与 ADR-0008 同一条硬约束）。
- 后续若要做用例图，建议复用流程图的分层布局，把 `actor` 画成独立形状即可，不必新写布局引擎。
