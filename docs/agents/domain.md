# 领域文档（Domain Docs）

工程类技能在探索本仓库代码时，应如何消费本仓库的领域文档。

本仓库为**单上下文（single-context）**：只有一个术语表和一个 ADR 目录，均位于仓库根目录。

## 探索之前先读这些

- 仓库根目录的 **`GLOSSARY.md`**（术语表）。
- **`docs/adr/`**：读与你要改动区域相关的 ADR。

如果这些文件不存在，**静默跳过**。不要指出它们缺失，也不要主动建议先创建它们。`/domain-modeling` 技能（经由 `/grill-with-docs` 与 `/improve-codebase-architecture` 触达）会在术语或决策真正被确定时，按需惰性创建。

## 文件结构

```
/
├── GLOSSARY.md
├── docs/
│   ├── adr/
│   │   ├── 0001-<决策>.md
│   │   └── 0002-<决策>.md
│   └── agents/          ← 本文件及其同级文件
└── src/
```

## 使用术语表的词汇

当你的产出要命名某个领域概念时（issue 标题、重构提案、假设、测试名称），使用 `GLOSSARY.md` 中定义的术语。不要漂移到术语表明确回避的同义词。

如果你需要的概念还没进术语表，这是一个信号：要么你在杜撰项目并不使用的语言（重新考虑），要么确实存在空白（记下来交给 `/domain-modeling`）。

## 标出 ADR 冲突

如果你的产出与既有 ADR 相矛盾，明确地把它摆出来，而不是悄悄覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重开讨论，因为……_
